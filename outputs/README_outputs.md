# outputs/ — what's here and how to read it

This folder holds THREE kinds of result. They are not interchangeable.

## 1. Reproducible reference — 9-provider freeze (current)
- `scores.csv`, `report.html`
- Generated by `python src/report.py` (offline) from the cached text in `corpus/`.
- Covers **9 providers**: the original 3 (Baillie Gifford, Moneybox, Trading 212)
  plus 6 more (Vanguard, abrdn, Fidelity, Fundsmith, Revolut, Monzo) whose text
  was captured live on **2026-08-05** and frozen into `corpus/*.txt` as plain text.
- **Deterministic:** re-running always yields the same numbers from this point on.
  Locked by `tests/test_canonical.py` (`test_three_provider_canonical` +
  `test_nine_provider_freeze_2026_08_05`). See SPEC.md §10 / §10.1.
- **Re-frozen 2026-08-05 (same day)** after fixing a word-count normalization bug:
  `trust_engine.py`/`bias.py` were computing "per 1,000 words" rates against a
  different (regex-token) word count than the one reported as `word_count` (plain
  split). Now both use the same count. Numbers in this CSV, SPEC.md §10/§10.1 and
  the tests are all post-fix.
- **BlackRock iShares is absent, not silently missing:** every live attempt against
  `ishares.com` on 2026-08-05 failed the coverage gate (anti-bot blocking). No
  reliable text exists to cache, so it is excluded from scoring and asserted
  absent by `tests/test_canonical.py::test_blackrock_excluded_pending_reliable_scrape`.
  Add `blackrock.txt` to `corpus/` and flip that test once a scrape actually clears
  `extract.MIN_WORDS`.

## 2. Scrape evidence for the 2026-08-05 freeze
- `fetch_log_2026-08-05.txt` — full per-URL fetch log (word counts, method,
  coverage status) from the live run whose output was frozen into `corpus/`.
- `../corpus_live_2026-08-05.zip` (repo root) — the raw live-fetched text for
  all providers that cleared the coverage gate that run, before merging into
  `corpus/`.

## 3. Earlier same-day capture — reference only, NOT reproducible, NOT the citable numbers
- `benchmark_live_10providers.csv` / `.html`
- An earlier live run on 2026-08-05 at 21:36, ~25 min before the freeze above.
  Scored all 10 providers (including a working BlackRock and Trading 212), but
  its underlying extracted text was never preserved, so it **cannot be
  reproduced or audited** and must not be cited as the project's numbers. It also
  predates the word-count fix above, so its numbers aren't comparable metric-for-metric.
- Kept only as a same-day comparison point. Diffing it against the frozen
  9-provider set above surfaced real deviations (word counts differing 1.7–2.8×
  across all 6 overlapping providers, Trust Index deltas up to ~26 points) — see
  SPEC.md §10.1 for the reconciliation. Vanguard's swing, initially unexplained,
  turned out to be the word-count bug above (its fund-listing page's ISINs/tickers/
  percentages were silently excluded from the old denominator). **Cite the frozen
  set in §1, not this file.**

## Why corpus/ has 9 providers, not 3 or 10
`corpus/` is the cached, plain-text corpus backing the reproducible reference in
§1. Two providers remain outside it: BlackRock (no reliable scrape yet — not a
missing-provider defect, see §1) and none of the fintech/asset-manager set are
excluded by choice. Adding BlackRock later is a "cache its text, add it to the
frozen test, extend the SPEC table" change — no code change needed, the pipeline
already scores whatever text is cached.
